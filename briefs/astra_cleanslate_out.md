**My bet: discrete latent attention trained by truncated expectation–maximization (EM).** Broad superiority is possible, but unlikely. The closest reachable outcome is better learning per second and per character on structured domains such as code.

1. **Mechanism.** Replace continuous attention heads with discrete routing modules. Each selects a previous position and a reusable latent symbol; stacked modules compose symbols into larger patterns. Fixed indexing proposes candidate positions. Learned categorical tables specify routing, symbol transitions, and next-character probabilities. During training, a small beam searches routing configurations using context **and the observed next character**. Normalize their probabilities; update every table using posterior-weighted counts plus smoothing. At inference, marginalize candidate routes using context alone. This is a proposed architecture, drawing on [probabilistic-circuit learning](https://proceedings.mlr.press/v119/peharz20a.html), not an established recipe.

2. **Speed and quality.** It removes dense reverse-pass computation and activation storage. Only selected routes receive count updates. Discrete reusable symbols could encourage compositional generalization and reduce interference; posterior credit uses the actual prediction target rather than unrelated local objectives. **There is no guarantee this preserves quality:** beam truncation loses credit information, and discrete representations restrict expressivity. Those are the central bets.

3. **Scaling.** Grow the symbol dictionary and expert count while keeping active routes bounded; shard tables and aggregate counts. That offers sparse computational scaling. Statistical scaling remains unproved: if useful inference requires a rapidly widening beam, the approach fails. Brain-inspired sparse assemblies motivate the representation, not evidence of superiority.

4. **Not disguised backprop.** No parameter update differentiates through an operation chain. Learning consists of discrete posterior inference and sufficient-statistic accumulation. Credit still travels across layers through posterior dependencies; eliminating derivatives does not eliminate credit-assignment work.

5. **Smallest kill test.** Compare roughly 1.2M stored parameters against GPT on a 6M-character subset, with equal tuning budgets and three seeds. Measure held-out loss versus both characters consumed and elapsed time, plus a held-out code family. Include indexing/search costs. Kill this implementation if it cannot improve **all three curves**; improvement only on familiar data also fails the generalization claim. This cannot disprove the entire architectural family.

6. **Closest alternatives.** [Predictive coding](https://arxiv.org/abs/2006.04182) can recover backprop gradients through iterative inference, threatening speed. [Forward-forward](https://arxiv.org/abs/2212.13345) offers local training, but its goodness objective provides weaker alignment with next-character likelihood.

7. **Odds.** My subjective probability of beating a well-tuned GPT on every requested axis **and retaining the advantage at scale: about 3%**. Likeliest failure: accurate routing inference costs more than backprop.
